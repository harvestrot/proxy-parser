# proxy-parser

Сборщик, проверщик и VPN-клиент на бесплатных прокси. Программа собирает прокси из
нескольких источников, строго их проверяет (настоящий HTTPS-запрос, проверка
сертификатов, UDP, реальная скорость), запоминает, кто как себя вёл, и строит из
лучших системный VPN (TUN через sing-box). Приоритет: **SOCKS5 → SOCKS4 → HTTPS**.

## Запуск

### Готовый exe (проще всего)

Скачай **`ProxyParser.exe`** со страницы
[Releases](https://github.com/harvestrot/proxy-parser/releases/latest), положи его
**в отдельную папку** (рядом с ним программа хранит список прокси, настройки и
sing-box) и запусти. Python не нужен. sing-box (~30 МБ) программа скачает сама при
первом подключении VPN — закреплённую версию 1.14.2 с проверкой SHA-256.

Exe не подписан цифровой подписью, поэтому Windows SmartScreen может показать
«Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом
случае». Некоторые антивирусы ложно срабатывают на любые exe, собранные
PyInstaller, — исходники открыты, exe можно собрать самому (ниже).

### Из исходников

Нужен Python 3.11+ (с python.org, при установке отметь «Add python.exe to PATH»).

Дважды кликни **`ProxyParser.bat`**. В первый раз он сам создаст окружение и
поставит зависимости, потом сразу откроется окно.

### Собрать exe самому

Дважды кликни **`build.bat`** — он поставит PyInstaller, соберёт
`dist\ProxyParser.exe` и проверит сборку (`ProxyParser.exe --selfcheck отчёт.json`
пишет отчёт без открытия окон).

- **«Обновить список»** — собрать и проверить прокси. Рабочие появятся в таблице;
  двойной клик по строке копирует адрес. В колонке **«Сеть»** — чья это сеть:
  «провайдер» (обычный домашний/офисный интернет), «мобильная» или «хостинг»
  (дата-центр), и название владельца — например, «провайдер · Bredband2 AB».
- **«Подключить VPN»** — весь трафик компьютера через лучшие прокси. В первый раз
  программа попросит перезапуститься от имени администратора: Windows требует
  этого для виртуального сетевого адаптера. sing-box подхватится из папки
  `sing-box-*-windows-amd64` или скачается с GitHub.
- **«Источники…»** — открыть `sources.json` (см. ниже).
- **«Автоподбор при VPN»** — если прокси в VPN начинают умирать, программа сама
  найдёт замену (см. ниже).
- **Правый клик по строке** в таблице — закрепить этот прокси для VPN (см. ниже).
- **«⚙ Настройки…»** — автозапуск, автоподключение, трей, фоновое обновление.

Под кнопкой VPN видно, через какой прокси идёт трафик, сколько прокси в группе
отвечают и как идут звонки. Полный лог sing-box — в `vpn\sing-box.log`.

## Автозапуск, трей, фоновое обновление — «⚙ Настройки…»

- **Запускать вместе с Windows** — программа стартует при входе в систему сразу в
  трей и **сразу с правами администратора, без окна «Разрешить изменения?»**. Для
  этого создаётся задание в планировщике Windows («ProxyParser VPN»): работает и от
  батареи ноутбука, и без ограничения по времени (у заданий по умолчанию через 72 ч
  Windows их завершает — здесь это отключено). Включить или выключить автозапуск
  можно только от администратора — программа предложит перезапуститься.
- **Подключать VPN сразу после запуска** — если список пуст, сначала обновит его.
- **Крестик окна сворачивает в трей.** Значок в трее показывает состояние VPN цветом
  (серый — выключен, жёлтый — подключается, зелёный — подключён), в подсказке — через
  какой прокси идёт трафик. Меню значка: открыть, подключить/отключить VPN, обновить
  список, выход. Если окно в трее, ошибки приходят уведомлением, а не окном.
- **Обновлять список в фоне** (по умолчанию — каждые 3 часа). Работающий VPN при этом
  **не перезапускается**, пока его прокси отвечают: перезапуск рвёт звонки и загрузки.
  Свежие прокси идут в дело при автоподборе и следующем подключении. Если включён
  сторонний VPN, фоновое обновление не задаёт вопросов, а откладывается на полчаса.

Программа запускается в одном экземпляре: если она уже работает в трее, повторный
запуск просто покажет её окно. Настройки — в `settings.json`.

## Закреплённый прокси и страны

- **Закрепить прокси** — правый клик по строке в таблице → «Закрепить для VPN»
  (строка подсветится). Весь трафик VPN пойдёт через него. Если
  он перестанет отвечать, программа сама временно переключится на автовыбор лучшего,
  а когда он оживёт — вернётся на него. «Открепить» — рядом с надписью «Прокси:».
- **Страны** — кнопка «Выбрать…» рядом с «Страны:»: отметить, из каких стран брать
  прокси (есть «Только Европа»). Ничего не отмечено — любые. Если в выбранных
  странах рабочих прокси не окажется, программа возьмёт любые и предупредит в
  журнале. На закреплённый прокси фильтр не действует.

## Маршрутизация по приложениям

Кнопка **«Настроить…»** рядом с «Маршрутизация» под кнопкой VPN. Три режима:

| Режим | Что идёт через прокси |
|---|---|
| **Весь трафик** | всё (по умолчанию) |
| **Только выбранные приложения** | только выбранные программы; всё остальное — напрямую, как без VPN. Если бесплатные прокси отвалятся, остальной интернет продолжит работать (DNS в этом режиме тоже идёт напрямую — через зашифрованный DoH к 1.1.1.1, провайдер его не подменит) |
| **Всё, кроме выбранных** | всё, кроме выбранных программ — они идут напрямую (удобно для игр, банков, всего, что работает и без VPN) |

Программы добавляются из списка **запущенных** (двойной клик; ● — у программы
есть окно; есть поиск), из меню **«Популярные»** (браузеры, Discord, Telegram,
Spotify, Steam, Epic Games — даже если сейчас не запущены) или кнопкой **«Выбрать
.exe…»**. У известных программ сами добавляются все их сетевые процессы (у Steam —
ещё `steamwebhelper.exe`). Правило работает по имени процесса, а не по пути, —
поэтому не ломается при обновлении программы.

Если VPN включён, новые настройки применяются сразу (перезапуск — около секунды).
Хранятся в `routing.json` в папке программы.

## Источники — `sources.json`

Файл создаётся при первом запуске в папке программы. Чтобы добавить источник,
допиши запись и нажми «Обновить список»:

```json
{"name": "мой список", "kind": "plain", "url": "https://.../socks5.txt",
 "type": "socks5", "enabled": true, "limit": 2000}
```

- `kind`: `plain` — текстовый список по ссылке (строки `ip:port`,
  `socks5://ip:port`, `ip:port:Страна`, `ip:port <что угодно>`; тип из строки
  важнее поля `type`; прокси с логином, частные и служебные адреса вроде
  `0.0.0.0` отбрасываются); `proxyscrape` — встроенный API proxyscrape.com
  (если он не открылся — его зеркало на GitHub).
- `type`: `socks5` / `socks4` / `http` — для строк без схемы.
- `limit`: сколько максимум брать за одно обновление (случайная выборка — за
  несколько обновлений пройдётся весь список, а хорошие запомнит репутация).
- `enabled`: `false` — выключить, не удаляя.

**Фермы — почему хорошие прокси перестали находиться.** По разбору списков 2
октября 2026 почти все публичные SOCKS5-списки на 50–85% состоят из портов
**одной фермы** — `45.74.31.0/24`: 10 IP и 31 тыс. портов, которые пересылают
трафик на чужие прокси (у monosans это 520 адресов из 677, у proxyscrape — 83%,
у proxifly SOCKS5 — 31 тыс. из 37 тыс.). Из одной подсети в VPN всё равно идут
максимум 2 прокси, а проверка тысяч её портов съедала лимиты источников, забивала
роутер и занимала весь замер скорости. Теперь с одного IP проверяется не больше
2 портов, из одной подсети /24 — не больше 6 адресов (случайная выборка: за
несколько обновлений пройдётся вся ферма; уже работавшие раньше прокси
проверяются всегда). В журнале это строка «лишних портов „ферм“».

Источники пересмотрены с учётом ферм (что дают после их урезания и что из этого
есть только у них; подробности — в `_note` и в комментарии в
`proxyparser/sources_config.py`):

| Источник | Зачем |
|---|---|
| **proxyscrape** | рабочие и быстрые прокси со страной (РФ отсеивается до проверки). Если их API не открылся (сайт proxyscrape — за Cloudflare, а Cloudflare из РФ режется: соединение «замирает» после ~16 КБ), те же данные берутся из их зеркала на GitHub |
| **proxifly SOCKS5** | вернулся: 31 тыс. его адресов были той самой фермой (из-за неё его раньше и вырезали); без неё — 2,7 тыс. разных SOCKS5, 1,4 тыс. из них нет больше нигде |
| **dpangestuw**, **vmheaven**, **ALIILAPRO**, **iplocate**, **openproxylist.xyz** | много SOCKS5, которых нет в других списках (iplocate вернулся: раньше был копией monosans) |
| **monosans**, **elliottophellia** | сдали (почти целиком ферма и РФ), но маленькие и часто перепроверяются; ради UDP (звонки) |
| **proxifly http** | HTTP-прокси (HTTPS через CONNECT): рабочих мало, но попадаются быстрые, которых нет больше нигде |
| **hproxy https** | новый: HTTP-прокси, прошедшие их проверку по HTTPS, только живые; 1,2 тыс. уникальных |
| **maximilianfeix https** | новый: прокси всех типов, прошедшие проверку сертификата TLS, ханипотов и подмены страниц |
| **monosans http** | вернулся: маленький, перепроверяется каждый час |

Не взяты: давно не обновляющиеся (ClearProxy, ProxyGather, zebbern, rdavydov…),
почти целиком ферма и копии оставленных (hproxy и maximilianfeix SOCKS5, VPSLab,
databay, TheSpeedX…), огромные непроверенные свалки на десятки тысяч адресов.
**GeoNode API** проверен 2 октября 2026: из ~3,8 тыс. его прокси 2335 нет в
списках выше, но рабочих среди них — 5, быстрый — 1 (Индонезия), в ближней
Европе — ни одного; лишние 2,3 тыс. проверок на каждое обновление не окупаются.

Прокси с UDP — редкость (≈2% рабочих SOCKS5), поэтому репутация их бережёт: такой
прокси считается «проверенным» после одной успешной проверки и перепроверяется
неделю, даже если пропал из списков, — запас копится от обновления к обновлению.

**Больше — не лучше.** Поток в десятки тысяч подключений забивает роутер и канал,
и проверка остальных проваливается. С урезанием ферм все источники вместе дают
около 9–12 тыс. разных адресов за обновление.

**Обновление программы.** `sources.json` живёт рядом с программой, и новые
источники сами в него не попадают. Если файл — нетронутые источники по умолчанию
прошлой версии, программа заменит его новыми (старый останется как
`sources.old.json`). Если в нём свои правки — он не трогается; чтобы получить
новые источники, переименуй его — при следующем обновлении он создастся заново.

В поле `_note` у источника — итог разбора («адресов / берётся после урезания ферм
и лимита / из них не в РФ и нет больше ни в одном источнике»). Если файл испорчен,
программа берёт встроенные источники и файл не трогает. Файл можно править в
Блокноте — он читается и в UTF-8 (с BOM и без), и в ANSI.

Лучшие прокси копятся со временем: репутация помнит всех, кто хорошо себя показал,
и перепроверяет их на каждом обновлении, даже если они пропали из списков.

**Какие источники лучше.** После каждого обновления в журнал выводится таблица:
сколько прокси дал каждый источник, сколько живых, рабочих, быстрых (от 500 КБ/с),
с UDP, сколько рабочих **в сетях провайдеров** (а не хостингов — см. «Провайдер
или хостинг» ниже) и сколько рабочих есть **только** у него. Итоги копятся по запускам в
`results\source_stats.json` — по ним видно, какие источники стоит оставить.

## Как проверяются прокси

1. **Кандидаты**: всё из источников + «проверенные» из репутации (прошли 2+
   проверки за 48 ч), даже если из источников они пропали.
2. **Чёрный список и «отдых»** (из репутации) — не проверяются вовсе.
   **Фермы** — с одного IP не больше 2 портов, из подсети /24 не больше 6 адресов
   (см. «Фермы» выше).
3. **Страна**: из источника или кеша. **Прокси из России отсеиваются** (правило
   в `filters.py`). У прокси без страны она определяется по IP после проверки
   (бесплатный ip-api.com) — только у рабочих, чтобы уложиться в лимит API. Тем
   же запросом у рабочих определяется **тип сети** — провайдер, мобильная или
   хостинг (см. ниже). Страна и сеть кешируются в репутации.
4. **Быстрый отсев**: открыт ли порт (2 с, 500 одновременно). Убирает 80–90%
   мёртвых за секунды — поэтому не страшно подключать списки на тысячи прокси.
5. **Полная проверка**: HTTPS-запрос через прокси с проверкой сертификата
   (gstatic / Cloudflare) **и** проверка сертификата 1.1.1.1 — через него VPN
   узнаёт адреса сайтов. Некоторые прокси «выборочно» подменяют сертификаты (то
   есть пытаются читать трафик) — такие отбраковываются как опасные и попадают в
   чёрный список навсегда. Сертификат gstatic проверяется ещё и **по IP — так,
   как подключается VPN**: sing-box просит прокси соединиться не с именем сайта,
   а с адресом, который сам узнал через DNS. 2 октября 2026 так попался
   `34.88.38.81:9443` — открытый наружу корпоративный шлюз FortiGate: по имени
   он пропускал честно (и был самым быстрым в списке), а по IP подменял
   сертификат почти на всех сайтах, и браузер показывал «Подключение не
   защищено». Если по IP просто не открылось — это не повод браковать, важна
   только подмена. У рабочих SOCKS5 дополнительно проверяется **UDP**
   (нужен для звонков): серия из 5 STUN-пакетов на обычный порт, вернуться
   должны минимум 4.
6. **Скорость**: у всех рабочих (до 300) качается кусок файла с
   speed.cloudflare.com — пинг не равен скорости. Места в замере сначала
   получают по 2 лучших из каждой подсети /24, потом остальные — ферма с малым
   пингом не вытесняет других. Прокси, через который данные не пошли, получает 0;
   медленный — свою реальную (низкую) скорость, а не «неизвестно». Если данные
   пошли и встали больше чем на 2,5 с (так ТСПУ режет зарубежные хостинги:
   Cloudflare, Hetzner, OVH, DigitalOcean — соединение «замирает» после ~16 КБ),
   замер прерывается сразу, а прокси получает честно низкую скорость.
7. **Репутация** обновляется: надёжность (сколько проверок из скольких
   пройдено), сглаженные скорость и задержка. Ни разу не работавший прокси после
   2 провалов подряд сутки «отдыхает» (в больших списках таких десятки тысяч).
   **Быстрые** (от 500 КБ/с) — как и прокси с UDP — считаются «проверенными» после
   одной успешной проверки и перепроверяются неделю, даже если пропали из
   списков: бесплатные списки то теряют, то снова находят один и тот же прокси,
   а лучшие находки так не теряются после первого же обновления. Хранится в
   `results\reputation.json`.

Колонка **«Надёжность»** в таблице — сколько проверок прокси прошёл из скольких
(«новый» — видим впервые).

## Как выбираются прокси для VPN

Главное — **реальная скорость и стабильность**.

- sing-box внутри группы выбирает прокси **по пингу, а не по скорости**. Поэтому
  в группу попадают только прокси с замеренной скоростью **от 500 КБ/с** **и**
  откликом до 2,5 с (через прокси с откликом 6 с каждое соединение открывается
  6 с, какой бы ни была скорость). Если таких нет — группа из прокси от 150 КБ/с.
  Если их меньше трёх — группа добирается до трёх: сначала прокси от 150 КБ/с,
  потом незамеренными.
- **Медленнее 150 КБ/с по замеру — в VPN не попадают никогда**, пока есть хоть
  кто-то быстрее. Только если быстрее нет вообще никого, VPN запустится на
  медленных, и в журнале будет предупреждение.
- **Стабильность**: прокси, который проверяли 4+ раз и который чаще падал, чем
  работал, берётся только добором в самом конце, когда стабильных не хватает.
- Порядок — по «ценности»: скорость × надёжность по истории × география
  (ближняя Европа — бонус, Азия/Латинская Америка — штраф: из РФ они почти всегда
  медленнее) × сеть (провайдер — бонус, хостинг — небольшой штраф, см. ниже) × тип.
- Для обычного трафика тип почти не важен (HTTPS-прокси через CONNECT не хуже
  SOCKS5), поэтому быстрый HTTPS не отбрасывается из-за медленных SOCKS5; при
  прочих равных SOCKS5 впереди. Если скорость не замерялась вовсе — порядок
  SOCKS5 → SOCKS4 → HTTPS.
- **Не больше 2 прокси из одной подсети /24.** Бесплатные прокси часто идут
  «фермами» — один оператор на десятках портов соседних IP. Если группа целиком из
  такой фермы, она падает разом, и весь трафик видит один человек.
- sing-box перепроверяет группу каждые 30 с, переключается только на заметно
  лучший прокси, а мёртвый бросает через 5 с.

**Провайдер или хостинг.** ТСПУ душит трафик к зарубежным хостингам (Hetzner,
OVH, DigitalOcean, Amazon, Oracle…: соединение «замирает» после ~16 КБ), а к
сетям обычных провайдеров — нет. По разбору 2 октября 2026 у рабочих прокси в
сетях провайдеров медианная скорость ~2 МБ/с, у хостинговых — ~70 КБ/с; все
прокси на Hetzner, Oracle, Amazon, Alibaba и Contabo давали 3–8 КБ/с. Лучшие
находки — HTTPS-прокси `85.8.47.x:7080` в Швеции (5,7 МБ/с, отклик 130 мс) — в
сети провайдера Bredband2. Поэтому при близкой скорости прокси в сети
провайдера идёт впереди хостингового (×1,2 против ×0,9). Это множитель, а не
фильтр: скорость всё равно замеряется, а среди хостингов бывают быстрые (Google
Cloud в Финляндии — 6 МБ/с); к тому же ip-api иногда ошибается в типе сети.

**Трафик самой программы идёт мимо VPN** (правило в конфиге sing-box). Поэтому
обновлять список можно при включённом VPN: проверка идёт с обычного подключения,
а в конце VPN перезапускается с новым списком (обрыв около секунды).

**Автоподбор.** Пока VPN включён, программа раз в минуту смотрит, сколько прокси в
группе отвечают. Если две проверки подряд живы не больше четверти — она
перепроверяет запасные прокси из последнего списка (медленные по прошлому замеру
в запас не берутся), **заново замеряет их скорость** и перезапускает VPN, только
если нашлось хотя бы три живых со скоростью от 150 КБ/с; иначе запускает полное
обновление. Не чаще раза в 5 минут. Нестабильные по истории проверяются в запасе
последними.

**Сторонний VPN.** Если при проверке включён другой VPN (WireGuard, Amnezia,
OpenVPN…), проверка покажет доступность прокси из его страны, а не с твоего
подключения, — программа заметит его и попросит выключить.

## Звонки (Discord и т.п.)

Голос идёт по **UDP**. Через HTTP- и SOCKS4-прокси UDP не проходит никогда, через
SOCKS5 — только если сервер поддерживает UDP ASSOCIATE (у бесплатных редкость), а
многие «поддерживающие» пропускают одиночный DNS-запрос, но теряют обычный поток
пакетов — поэтому проверяется серия пакетов. Если такие прокси нашлись (TCP-
рукопожатие с ними быстрее 4 с, скорость не ниже 30 КБ/с), весь UDP идёт через
отдельную группу из них; если нет — **голос Discord идёт напрямую, мимо VPN**.
QUIC (UDP 443) отклоняется, чтобы браузер сразу шёл по обычному HTTPS.

**Онлайн-игры** (Roblox и т.п.) через бесплатные прокси нормально не работают:
игре нужен стабильный UDP с маленьким пингом, а таких бесплатных прокси почти нет
(на проверке — 2–4 прокси с UDP из ~130 рабочих, с потерями пакетов и пингом
около 300 мс). Для игр нужен нормальный VPN.

## Консольный режим

`python main.py scrape | check | all | vpn-config` (проверка — тем же
конвейером, что и в окне) и скрипты `vpn\*.ps1`. Подробности: `python main.py --help`.

## Важно про бесплатные прокси

- Они **недолго живут** — отсюда автопереключение, автоподбор и репутация.
- Их трафик до прокси **не шифруется** (видно, куда ты ходишь), а оператор прокси
  может пытаться читать HTTPS — программа ловит подмену сертификатов, браузер тоже.
  Если браузер показывает ошибку сертификата — не продолжай на сайт.
- Для важного (пароли, платежи) — лучше свой нормальный VPN.
